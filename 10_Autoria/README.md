## Notas de campo y sesiones de elicitación

La carpeta [`notas_campo/`](notas_campo/) contiene **30 archivos
documentales** asociados con las jornadas diferenciadas del corpus final.

Estos archivos se clasifican de la siguiente manera:

```text
Notas contemporáneas:       8
Síntesis retrospectivas:   22
Total de archivos:         30
```

Las 8 notas contemporáneas corresponden a sesiones realizadas el 17/06/2026.

Para las otras 22 sesiones no se conserva una nota escrita durante la sesión
original. Las hojas correspondientes fueron elaboradas el 17/09/2026 a partir
de las transcripciones previamente conservadas y se identifican expresamente
como **síntesis retrospectivas**.

Las síntesis retrospectivas no se presentan como notas tomadas durante la
fecha original de la entrevista o del walkthrough.

La correspondencia detallada entre:

* fecha;
* participante;
* tipo de sesión;
* transcripción o transcripciones asociadas;
* nota contemporánea o síntesis retrospectiva;
* estado;
* observación;

se encuentra documentada en:

[`bitácora_sesiones/bitacora_elicitacion.csv`](bitácora_sesiones/bitacora_elicitacion.csv)

El número bruto de archivos de transcripción no se interpreta como número de
sesiones independientes, ya que una misma jornada puede producir varias
transcripciones por separación de fases, división en partes o conservación de
variantes históricas.

## Inventario de integridad

La carpeta [`inventario_exif/`](inventario_exif/) contiene el archivo:

[`inventario_exif.csv`](inventario_exif/inventario_exif.csv)

El inventario documenta, según corresponda:

* ruta del archivo;
* tamaño en bytes;
* fecha de captura EXIF;
* modelo del dispositivo;
* presencia o ausencia de GPS;
* hash SHA-256.

Cuando un archivo no contiene metadatos EXIF suficientes, dicha ausencia se
registra expresamente y no se fabrica información para completar el inventario.

Después de renombrar, añadir, eliminar o sustituir evidencias, el inventario
debe regenerarse antes de establecer la etiqueta final del repositorio.

## Criterios de integridad

* Los nombres e identidades Git se normalizan mediante `.mailmap` sin modificar
  ni eliminar commits históricos.
* Las contribuciones históricas permanecen acreditadas a sus autores reales.
* Se diferencia entre notas contemporáneas y síntesis retrospectivas.
* No se crean capturas, sesiones, firmas, fechas o evidencias ficticias.
* La falta de una firma, fecha o respaldo se declara cuando corresponde.
* Los archivos multimedia se verifican mediante tamaño y SHA-256 cuando
  corresponde, aunque no contengan metadatos EXIF.
* Las diferencias entre el número de archivos y el número de sesiones se
  documentan mediante la bitácora de elicitación.
* Los cambios posteriores al cierre requieren actualizar los inventarios y
  checksums antes de crear la etiqueta final.
* La transferencia de propiedad del repositorio no modifica la autoría de los
  commits históricos.
