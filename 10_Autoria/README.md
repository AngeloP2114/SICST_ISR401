## Notas de campo y sesiones de elicitación

La carpeta [`notas_campo/`](notas_campo/) contiene **30 notas de campo o
síntesis** asociadas con las jornadas diferenciadas del corpus final.

La correspondencia detallada entre:

- sesión;
- participante;

- nota de campo;
- observación;

se encuentra en:

[`bitácora_sesiones/bitacora_elicitacion.csv`](bitácora_sesiones/bitacora_elicitacion.csv)

El número bruto de archivos de transcripción no se interpreta como número de
sesiones independientes, ya que una misma jornada puede producir varias
transcripciones por división en fases, partes o conservación de variantes
históricas.

Las síntesis elaboradas posteriormente se identifican expresamente como
retrospectivas y no se presentan como notas tomadas durante la fecha original.

## Bitácoras

La carpeta [`bitácora_sesiones/`](bitácora_sesiones/) contiene dos tipos de
registro:

### `bitacora_sesiones.csv`

Reconstruye actividad de desarrollo a partir del historial Git y documenta:

- fecha;
- integrante;
- intervalo horario;
- número de commits;
- resumen de actividades.

### `bitacora_elicitacion.csv`

Documenta las sesiones reales de elicitación y validación y su relación con
las transcripciones y notas de campo.

Ambos archivos cumplen funciones distintas y complementarias.

## Criterios de integridad

- Los nombres e identidades Git se normalizan mediante `.mailmap` sin modificar
  commits históricos.
- Las contribuciones históricas permanecen acreditadas a sus autores reales.
- Las notas reconstruidas se identifican como retrospectivas.
- No se crean capturas, sesiones, firmas o evidencias ficticias.
- La falta de una firma, fecha o respaldo se declara cuando corresponde.
- Los archivos multimedia se verifican mediante tamaño y SHA-256 aunque no
  contengan metadatos EXIF.
- Las diferencias entre número de archivos y número de sesiones se documentan
  mediante la bitácora de elicitación.
- Los cambios posteriores al cierre requieren regenerar inventarios y
  checksums antes de crear la etiqueta final.
